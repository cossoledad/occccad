## 2. 问题判断与修复方向

### Main Fan：先恢复可靠引用，再验证孔

主文档：`documents/01a10b4e-f4c5-7088-9158-0a11908189e3`；读取 Head 为 `01a10c3c-e6f9-7294-ade7-8f51fea8a951`，状态 READY。模型已有 Extrude 4 → Fillet 1（R15）→ Pattern 1；阵列为 `FEATURE_DELTA`，从 Extrude 4 包含至 Fillet 1，绕标准 Z 整圆均布，数量 2。Sketch 5 已保存，通过替代引用继续建模不证明原目标引用有效。

- **FACE #2 无法建草图**：`FAILED_SUPPORT / PERSISTENT_SELECTION_AMBIGUOUS` 表示支撑解析获得多个有效候选，不能据此判定面不平或阵列禁止编辑。当前[拾取与解析](../../services/internal/workspace/topology_selection.go)默认创建 `LINEAGE_DESCENDANT` 配方，并沿真实历史收集候选；分裂、阵列复制或同阶段生成关系都可能扩大候选。须读取报错时的 Naming，确认 FACE #2 的语义锚点、候选、Body、显示阶段和成员，区分真实一对多与解析器在同一 transition 内扩张/阶段绑定错误。拾取时唯一的当前面与未来重算后的真实歧义也必须分开处理；不能全局改成直接引用而失去后续历史跟踪。
- **Sketch 5 无法投影 Extrude 4 的 EDGE #6**：可能共享上述引用问题，但尚无该次失败请求和候选证据。另有独立能力边界：当前[Worker 入口](../../workers/geometry/src/main.cpp)仅接受 Vertex、LINE Edge、CIRCLE Edge；[投影器](../../workers/geometry/sketch/src/external_geometry_projector.cpp)拒绝部分圆弧和倾斜圆，并拒绝投影退化成点的直线。应先确定 EDGE #6 的精确类型、有限参数域、引用解析结果及投影方向，再与可用的 EDGE #15/#20 比较。不能把更换边作为修复，也不能仅凭名称认定生成来源。
- **垂直截面放样孔**：复现文档 `documents/01a10c91-f088-7219-b2fb-015376aad2d1`，读取 Head `01a10c92-d53a-77d4-bbe4-315b415ebf01`，READY，只有两个草图。支撑分别为 XY 和法向 `(0,-1,0)`、原点 `(0,-30,0)` 的基准面，确为垂直布置。报错 Feature `loft-438ad24e-734a-5299-8b42-17f2bf542f2b` 未进入 Head；最近失败命令查询未取得该请求，不能恢复完整放样选项。当前[放样实现](../../kernel/occt/src/occt_kernel.cpp)在构造成功、实体检查之后进行自干涉检查，该错误来自此门禁。垂直截面本身不等于不可行；应补齐失败候选，检查截面位置、闭合起点、方向、对应关系及侧面/端盖交会，分别验证工具体放样与后续切除。不得跳过检查或用自动增加截面掩盖错误连接。

局部 FACE/EDGE 编号只用于对应报告，后续复现必须固定 Revision、配套 BREP/Naming 和 PersistentSelection。修复仍复用现有模型、真实 History 和选择体系；不靠最近几何、名字或“最后修改者”补配，不放开任意特征组重执行。

### Windmill Head Cover：几何直线与底层表示分开

现有放样以精确轮廓边组装截面，再交给 `BRepOffsetAPI_ThruSections`；类型查询按底层曲线报告。因此“看起来直”与底层 `BSPLINE_CURVE` 可以并存，尚不能确定是放样转换、后续布尔还是类型识别问题。应检查底边的精确曲线、参数范围和全域直线性。确为直线时，优先保留原解析边；需要解析识别或规范化时统一服务于轴选择、投影和属性查询，明确容差并保留真实映射。仅修改类型标签、按显示折线判断直线或改变曲面造型均不充分。

### Bottom Support：减少手算，同时保留设计依赖

- **标准轴选择/hover**：视图区选择能定位树，而树选择不能突出轴、视图 hover 不能提示树，说明双向身份与预选投影需核对，不能直接断定是渲染颜色错误。统一标准轴的轴系 ID＋X/Y/Z、基准 ID、文档/Revision/occurrence；主选择、预选和树提示分别管理，避免回调升级选择。
- **关联基准**：当前[基准编辑器](../../web/apps/cad/src/features/workbench/datum-editor.tsx)提供自由坐标、按参考复制及沿自身方向偏移，最终提交数值框架；参考不形成完整关联旋转/平移定义。后续应在现有 Datum 定义中表达“来源基准＋绕引用轴/直线旋转＋沿引用方向平移”，角度/距离绑定 ParameterId。标准面/轴、基准面/轴、草图线和实体边按角色接入，明确有限边与无限方向、右手方向、变换顺序及失效引用；非直曲线不能被静默当成旋转轴。编辑、预览、依赖检查、重算、Undo/Redo 一并贯通。
- **Origin 与投影**：可增加显式 Part 原点入口；装配中的 Part 原点随 occurrence 变换，不等同于装配世界原点。原点、标准轴与基准轴投影先覆盖点/方向/退化结果，再扩展圆弧、椭圆与一般曲线。面投影必须明确选的是边界投影、截交还是轮廓，不能把整面当作一条曲线。结果仍保存关联输入和更新状态，不以离散线段充当权威曲线。
- **参数入口**：当前参数对话框为 M 尺寸、逐行列出，操作按钮较多；已有别名表达式和稳定 ParameterId 绑定，`r_2` 引用 `r_1` 的需求主要是入口与反馈优化，不需要另建表达式系统。加宽、限制视口高度、内部滚动/固定表头，树按所属 Feature 组织；提供搜索及“插入参数引用”，编辑 r_2 时直接插入 r_1 并追加 `+5`。长度常量须按明确单位解释，提交前显示计算值及量纲、循环、重名错误；别名重命名不改变既有依赖。

## 3. 统一错误反馈与最小诊断入口

现有[操作反馈](../../web/apps/cad/src/cad/command/operation-feedback.tsx)已归一化部分命令错误，但预览、字段错误和 Feature 求值状态仍需统一关联。复制按钮直接调用 `navigator.clipboard.writeText`，没有可用性检查或失败反馈；非安全上下文、权限或 API 不可用是待核实原因，不能宣称已复现。应增加异常处理及可手动复制的回退，成功后才提示已复制。

| 错误阶段 | 建议展示与动作 |
|---|---|
| 本地确定非法：缺输入、数量/单位/零向量等 | 字段内说明、禁用提交；不凭几何猜测“大半径必非法” |
| 后端预览失败：求解、支撑、拓扑、几何 | 表单内摘要＋诊断入口；清除旧成功候选，不推进 Head |
| 正式应用失败：CAS、权限、过期预览、持久化等 | 统一通知；按代码提供刷新、重选或重试，不能无条件重发 |
| 上游修改导致下游失败/阻塞 | 树与面板标明首个失败及受影响依赖；区分候选失败、已接受 Revision 和上次成功显示 |
| 异步 Job、断连/超时、制品加载或显示快照不一致 | 显示任务/连接/制品状态；确认提交状态后再重试，避免重复操作 |

统一的是结构化失败合同与诊断关联，不是把所有情况都塞进同一个弹窗。保留阶段、稳定错误码、原因链、恢复动作及字段/Feature 定位；通知、预览和树状态共用 correlation，避免重复弹窗。须先核对现有“拒绝修改”与“接受失败模型”的实际合同，再确定各阶段保留哪个 Revision。

**建议最小反馈**：复制一行 `diagnosticId + code`；服务端通过现有[诊断包](../../services/internal/api/diagnostic_bundle.go)扩展检索，按失败时快照而非反馈时最新 Head 返回上下文。包应索引失败候选/规范命令、请求/预览/Job/attempt/trace、文档与基准 Revision、Feature/Body/阶段、occurrence/成员、选择配方及候选、参数/依赖摘要、BREP/Naming/GLB 制品引用与 evaluator/kernel 版本。日志按关联 ID 定位，不要求用户复制整个模型或日志。

失败预览尤其需要保留短期不可变候选及诊断记录，不能只依赖正式命令日志，也不应为诊断创建业务 Revision。明确保存期限、删除/过期提示和文档访问权限，排除凭据。本地校验或离线失败没有服务端 ID 时，复制包含阶段、文档/基准 Revision、操作和字段原因的最小文本；无法恢复已过期的候选时如实说明。上述机制为待实现设计，现有下载接口不是完整的按诊断 ID 查询服务。

## 4. 开发顺序与定向验收

1. **诊断基础与 Main Fan 引用阻断**：先打通可靠复制、失败预览留存和快照检索；固定 FACE #2、EDGE #6 的真实候选，修复选择配方/阶段或明确补齐投影能力。验收阵列前后、种子/成员、上游编辑和重开，保留真实歧义与失效引用检查。
2. **垂直放样孔与直线边识别**：取得失败定义后建立真实 Worker 定向复现，验证显式对应、合法工具体及切除；检查顶盖底边能被正确用作方向和投影输入。保留自干涉、实体有效性和真实 History 门禁。
3. **Bottom Support 参数化体验**：先轴选择/预选和原点，再关联基准旋转/平移、基础投影与参数引用 UI；复杂曲线/面投影按目标需求逐项扩展。改变倾角、高度及 `r_1` 后，基准、草图和 `r_2` 自动更新，不依赖手算重填。
4. **整体收口**：五类零件完成名义几何对照与参数扰动，再验证六实例静态装配、共享 Solar Panel、安装相位和引用更新。运动验收仍与静态装配分开。

开发验证采用受影响 Go、TypeScript 和真实 Router/Worker 定向场景，覆盖预览不写 Head、失败恢复、Undo/Redo、冷重开、多 occurrence 与成员隔离；复杂交互/颜色/布局另列人工验收。本文只完成分析与计划，不追加代码测试通过声明。
