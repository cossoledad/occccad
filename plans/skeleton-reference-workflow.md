# 骨架与跨零件引用流程设计

状态：设计，未实施新增骨架类型、带链接复制或新的引用编辑器。当前唯一 CAD 主线为 [CAD 核心主线](cad-core-roadmap.md)，已交付的引用能力及限制由 [Product 合同](../docs/architecture/current/product-assembly.md)拥有。本方案承接移除“关联更新与修复”面板后的流程梳理，不替代内部 UpdatePlan。

## 判断与依据

骨架应是组织设计意图的角色：集中总体尺寸、安装面、中心线和接口位置，让多个零件按同一组输入设计。可以有总体骨架和多个模块骨架，不应要求唯一全局骨架，也无需先新增文档种类。普通 Part 的参数、参考元素、草图和几何图形集适合作为承载者；纯标量可以由 Product 参数承担。子 Product 通过发布转发公开模块接口，内部结构保持私有。

不能把“约束零件位置”和“让零件形状受来源驱动”合并：前者改变 occurrence 位姿，后者改变 Part 定义或 ContextVariant。骨架不天然固定运动、不参与碰撞过滤，也不能因隐藏而停止求值。可选的“骨架”角色标识和默认显隐属于后续交互选择，不是本轮新增业务类型。

以下 CATIA B33 手册经 MCP 检索并读取相应正文/章节；它们支持引用机制的理解，并非本软件或真实 CATIA 模型的执行证据：

| 页面 | 手册事实 | 本项目取舍 |
|---|---|---|
| `online/asmug_C2/asmugrf0200.htm`，Designing in Assembly Design Context | 区分 External references 与 External parameters；保留链接、隔离、发布、同步及循环检测 | 复用正式发布、接收对象和依赖图，不将所有问题汇集成修复命令 |
| `online/cfyugkwr_C2/cfyugkwrparameters0015.htm`，Creating an External Parameter | 复制来源参数，在目标 Part 使用 As Result With Link，建立本地参数和来源链接；类型不兼容时报错 | 消费端需要可追踪的本地参数身份；不复制其 Product 外部参数自动更新集成不完整的限制 |

骨架数量、依赖方向、接收对象编辑方式是结合工程协作和本仓库的设计判断，不宣称来自某条 CATIA 强制规则。

### 与 Creo 的对照

PTC 的 [About Skeleton Models](https://support.ptc.com/help/creo/creo_pma/r13/usascii/assembly/asm/About_Skeleton_Models.html) 区分标准骨架和运动骨架；开启配置后允许多个标准骨架，并对树顺序、BOM 与物理属性赋予专门语义。它说明专用骨架类型是可行的完整产品方案，但不能只增加一个图标就继承这些保证。本软件当前采用普通文档承载角色；若未来增加 BOM 排除、质量排除或运动骨架，须单独设计，不因名称叫 Skeleton 自动改变业务行为。

[Copying Geometry in Top-Down Design Methodology](https://support.ptc.com/help/creo/creo_pma/r13/usascii/assembly/asm/Copying_Geom_in_Top-Down_Design_Methodol.html) 介绍总体骨架将设计准则传给子装配，子装配增加自身设计意图后继续向下分发；也指出把细节零件反向复制回骨架会增加来源失效和循环风险。由此采用“总体布局 → 模块布局 → 业务零件”的推荐依赖方向，多个来源分别进入稳定接收输入；已有零件的自底向上适配应通过明确的隔离输入或受控来源完成，不默默建立双向引用。

以上对照是官方文档行为与本项目取舍，不是跨软件操作测试。本项目保留参数和几何类型合同、不可变接受 Revision 与显式 occurrence，不照搬 Creo 的文件类型、配置开关或每装配数量限制。

## 推荐操作流程

1. 总体设计者创建普通 Part“总体布局”，维护安装间距、厚度、轴线、基准面和接口草图。只发布稳定、明确用途的输出，如“安装间距”“安装面”“主轴线”；内部倒圆角面等偶然几何不作为长期协作接口。
2. 在 Product 中插入布局和业务零件。需要模块封装时，由子 Product 转发模块公开输出；消费方选择模块发布，保留该公开边界，不绕过它引用内部私有元素。
3. 编辑业务零件的具体参数、参考元素或特征。数值字段直接输入公式；需要外部来源时，在该输入处选择发布参数，创建或复用目标本地参数。几何输入处选择兼容发布，创建或复用本地参考输入。确认前只预览，取消不得遗留参数、槽位或绑定。
4. 确认时保留目标 ParameterId/DatumId/ContextInputId，保存来源文档、PublicationId、确切接受 Revision；涉及装配位置时同时保存完整 InstancePath 和相对变换。下游公式和特征引用本地接收身份，来源重定向不重建全部下游。
5. 修改布局后，消费对象显示待更新及来源；正常可计算引用沿既有跟随策略处理，需跨 Part 重算的输入显式接受。更新先验证来源，再求值接收对象，最后推进 owning Product；失败保留合法接受结果及真实诊断。
6. 来源断链时，在原参数、参考输入、发布或约束编辑器中更换元素。编辑器只显示当前输入、来源和必要错误；结构树定位接收对象并展开必要祖先。无需先打开全局修复面板。

一个零件可同时消费“总体布局”的安装位置和“传动布局”的轴径。每个引用明确自己的来源，不用“当前骨架”隐式改变所有输入。来源角色不决定优先级；相互依赖须保持有向无环，必要反馈由设计者改为上游独立输入。

## 共享定义与装配上下文必须明确

| 需求 | 接收位置与影响 | 已有基础 |
|---|---|---|
| 标准支架的孔距始终跟随某设计参数，所有装配中的同一 Part 都改变 | Part 本地参数的 ExternalParameterRef；修改共享定义 | 已有参数发布引用和参数更新计划 |
| 同一 Part 在左右两处按各自周边输入生成不同结果 | occurrence 的 ContextInput + ContextBinding + ContextVariant；不改共享默认定义 | 已有直接可编辑 Part 实例上下文 |
| Product 总体尺寸用于组织接口或转发给下层 | Product 本地参数/发布为来源；下层仍有显式接收对象 | 已有 Product 参数与发布；具体消费者类型按当前能力开放 |
| 几何结果带链接复制进另一个 Part | 目标本地引用结果及来源；不是插入新的同引用实例 | 尚无通用带链接复制命令；任意曲面/实体输入未交付 |

默认继承当前编辑范围，但确认必须能辨认“共享零件”与“当前实例”。不能因用户在 Product 中双击了参数就悄悄把定义引用改为 occurrence 引用；也不能让含 InstancePath 的几何引用脱离上下文时按另一实例猜测位置。

## 呈现和对象归属

参数继续显示在所属对象的参数树中；引用值不可直接覆盖为本地数值，需要在原编辑器明确更换来源或转为本地。只读属性展示来源与接受状态，修改经正式 Command。公式名称用于输入和展示，持久 AST 绑定稳定 ParameterId，改名不破坏关系。

几何引用置于消费 Part 的几何图形集/外部输入分组；树节点代表本地接收对象，展开后可查看来源。是否单列“外部引用”分组需在实现前对照现有 ContextInput 树，避免同时出现两份可编辑节点。选择本地输入高亮本地结果，查看来源才定位来源几何；重定向来源保持本地选中身份。

双击编辑是统一入口。参数输入、基准定义、草图外部元素和装配约束复用选择、来源呈现、清除和定位控件，但保留各自领域命令。不要新增一个可以修改所有关系的泛化修复编辑器。若未来需要大型依赖分析，可做只读关系浏览，跳转回对象编辑；不预先实现此功能。

## 更新、替换和故障

内部仍复用 UpdatePlan、依赖端口、来源快照、健康检查和 CAS；本轮删除的是独立 UI 工作流。连接状态、输入时效、计算结果和固定策略是不同维度，不能将有旧合法结果的 Pending 一律标 Broken。旧结果可显示并带过期状态，不可冒充新的公式/几何输入。

替换组件继续在两个确切公开边界按当前严格兼容规则建立对应，提交后保存新接口 ID。对应失败保留断链原身份，用户在消费对象更换来源；不能按近似形状、显示名或面序号恢复。接收 Part 被替换时，其本地槽位不属于新 Part，禁止按同名参数继承绑定。

固定来源保留确切接受 Revision，恢复跟随需重新检查来源。转为本地保留接收身份和最后合法输入，删除来源绑定并重算下游；无合法快照则拒绝凭空本地化。删除仍有消费者的本地接收对象必须走原依赖门禁。权限、单位维度、几何类型、循环、来源失败、CAS 变化和迟到预览均在提交前验证，失败不采用错误候选。

## 当前缺陷与后续实施顺序

当前 `ParameterExternalEditor`、`Design Inputs` 与 `DesignAssociationDialog` 已分别支持参数引用、本地槽位与绑定，但创建接收对象和指定来源仍分散；跨对象字段复用和树中接收对象归属也未统一。接收端仅开放当前 owning Product 的直接 Part，来源仅开放当前受支持发布，尚无任意深层接收、任意曲面/实体 Feature 输入或批量传播事务。不能把移除面板视为这些能力已补齐。

后续先完成一个“发布标量 → 接收参数 → 特征公式”的完整流程，统一输入处引用及对象内更换来源，并验证共享定义/单 occurrence 的区别。再收敛参考点线面和草图输入的本地对象呈现；最后才引入类型明确的带链接复制与更深层级编排。实施前对新增对象/命令及跨文档一致性另行评审，本方案不承诺新 schema 或兼容层。

最低验收应包括：多骨架输入、重复 occurrence 独立性、参数改名/单位、发布重定向/抑制/删除、替换兼容与不兼容接口、循环拒绝、固定/恢复跟随、来源失败后恢复、Undo/Redo、冷读重建、取消无残留、并发 CAS 与迟到结果。浏览器需验证从消费字段完成引用和修复，不通过全局面板绕过操作流程。
