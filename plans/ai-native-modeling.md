# AI 原生建模实施计划

> 状态：设计框架，尚未实施。目标是在右下角对话栏描述建模意图，由 AI 调用正式 CAD 能力，用户能观察每个步骤并随时接管。本文只保存待实施范围与退出条件，不构成 API、模型厂商或性能承诺。

## 接入方向与已有基础

采用服务端单 Agent，复用现有模块化 Go 控制面；先建立统一 CAD Automation API，再接入模型原生工具调用、MCP 或 CLI。内置 AI 使用模型工具调用；MCP 面向外部 Agent，CAD CLI 面向脚本和无界面自动化，均复用同一业务实现。模型厂商与 Agent Runtime 可替换，首版不以独立微服务、向量数据库或通用代码执行为前置。

已有基础与事实入口：

- [领域命令、Revision、CAS 与历史](../docs/architecture/current/model-history.md)：复用确定性 handler、权威求值、幂等提交和补偿历史。
- [命令公共框架](../docs/architecture/current/document-command-framework.md)：复用呈现目录、CommandRegistry 与交互生命周期；补充机器可读的操作合同。
- [编辑上下文](../docs/architecture/current/product-edit-context.md)与[语义树](../docs/architecture/current/semantic-tree.md)：沿用宿主、目标、Body、occurrence 和稳定身份；补充有界快照查询。
- [Realtime 与 Preview](../docs/architecture/current/realtime.md)：复用回执、Outbox、候选和取消门禁；补充任务恢复与实际显示确认。

```text
右下角 AI 面板 ↔ Agent Runtime ↔ LLM Adapter
                      ↕
              CAD Automation API
               ├─ 快照查询 / 派生索引
               └─ 授权 / 校验 / 预览 / 提交
                      ↓
       现有 Domain Command → evaluator / Worker → CAS
                      ↓
              Revision / 回执 / 实际事件 → UI
```

建议新增逻辑模块 `services/internal/automation`（操作与查询）、`services/internal/assistant`（任务与上下文）和 `web/apps/cad/src/features/assistant`（对话与步骤）。名称与接口在实施时确定；共享现有领域实现和权限边界，浏览器凭证与 LLM 凭证分离，后者留在服务端。

## 必须补齐的合同

| 合同 | 待实施内容 |
|---|---|
| 语义操作 | 每项操作登记稳定 ID/版本、简短 CAD 语义、输入输出 schema、单位/坐标系、前置条件、效果、能力限制和结构化错误。粒度使用草图编辑、拉伸、参数修改等领域动作；schema 尽量由领域输入合同生成，并检查描述与处理器一致性。 |
| 按需发现 | 初始只提供上下文、操作发现、模型查询和动作准备/提交等少量入口；检索后加载相关 schema。示意入口为 `context.get`、`operations.search/describe`、`model.query/read`、`actions.prepare/commit`，均非当前 API。 |
| 快照查询 | 支持限定文档/子装配/Body、字段投影、聚合、局部依赖、精确读取和稳定分页；绑定 Revision、已解析依赖及必要的几何/上下文身份。索引由 Revision 派生并可重建，Web 与 AI 共用查询能力。 |
| 集合完整性 | 返回数量、分页/截断状态与预算诊断。批量动作引用绑定快照的完整 `selectionSet`，少量展示样本不代表全部；不能静默遗漏。查询成本与批量执行额度受服务端限制。 |
| 身份与权限 | 短引用由服务端映射到 typed stable ID、完整 InstancePath、Revision 及必要的 PersistentSelection；名称仅辅助搜索。查询、恢复与提交均检查目标和引用权限，区分定义与 occurrence，明确修改共享定义的影响。 |
| 读写一致性 | 将 AI 读取的快照作为准备和提交的共同基线；统一校验用户、目标、操作版本、参数摘要与依赖。复用现有 CAS，禁止将旧意图自动套用到新 Head。 |

LLM 使用自身语言与 CAD 概念知识理解目标、规划步骤；应用按需提供当前操作合同和模型事实。企业规范与专用知识包携带来源/版本。统计、几何计算、重复处理和求解交给确定性工具；常见流程逐步沉淀为版本化 recipe，仍展开成可观察的正式操作。

## 上下文、执行与恢复

每轮只组装“简短规则 + 用户目标/硬约束 + 编辑上下文 + 当前操作合同/模型工作集 + 最近步骤”。完整树、全部 schema 和历史工具结果留在服务端按需读取；不把 BREP、Mesh 或完整 Naming 填入上下文。稳定前缀可缓存，预算为输出及后续查询预留空间。

任务持久记录目标、已确认假设、计划、对象引用、步骤状态和提交回执；检查点可重新读取，摘要不能替代模型事实。每步在执行前分配稳定 requestId，重试保持相同意图；改变意图产生新请求。失联或超时先恢复回执，再决定后续动作，避免重复建模。

```text
定位与读取 → 形成操作 → 校验基线/输入 → 权威预览
→ 按任务授权提交 → 恢复回执 → 显示结果 → 下一步
```

- 用户的明确建模任务授权当前目标和范围内的连续操作；歧义、批量删除或影响范围扩大时暂停确认。权限、预算和提交许可由执行器强制判断，模型内容与导入文本按数据处理。
- 人工接管在当前操作结束屏障后暂停后续写入；重新读取人工修改后的基线。默认失联后在操作边界暂停，后台继续须有明确任务策略。
- Preview 保持短期、可撤销且不推进 Head；恢复时按需重新预览，不把候选当作长期任务状态。数值失败保留结构化诊断，修复尝试有界，不自动削弱硬约束、单位或容差。
- 每个有意义的步骤拥有清晰事务边界；任务可能部分完成。沿用现有历史并记录 AI/task/step 来源；整个任务撤销与跨文档原子操作需要另定合同。
- 单轮上下文受预算约束，不代表后台查询或求值成本与模型规模无关；两者分别测量。

## 简要 UI

右下角收起为输入栏，展开为“当前目标/选择标签 + 对话 + 步骤时间线 + 输入”。发送时冻结 `@选中对象` 引用；默认在任务范围内自动逐步执行，可切换逐步确认。提供暂停、接管、定位对象、参数/诊断详情及有明确目标的历史操作，复用既有表单、拾取和高亮。

时间线分别显示“已规划、预览就绪、已提交、已显示”，依据来自计划、evaluator、提交回执和浏览器显示确认。逐步观看时，显示完成再推进下一步；数据库事务不等待浏览器渲染。布局避让现有视口控件，模型刷新沿用权威 Query，面板和临时高亮归交互状态。

首版预览当前一步；多步整体预览需要 draft workspace 或等价候选模型，作为后续能力。

## 实施顺序与退出条件

| 顺序 | 范围与退出条件 |
|---|---|
| Part 最短闭环 | 贯通共享授权边界、有限操作目录、带快照/预算的查询、任务回执与 UI；完成“当前 Part 的 XY 草图 → 80×50 mm 矩形 → 拉伸 12 mm → 修改参数”。真实 evaluator/Worker、预览、历史、暂停接管和每步显示均有证据。 |
| 规模与长任务 | 补齐派生索引、集合查询、recipe、检查点和恢复；用数万节点、重复定义及长步骤任务验证完整性、权限和上下文预算，不因压缩丢失硬约束或对象身份。 |
| 接入与领域扩展 | 增加 MCP/CLI 适配器，再按实际需求扩展装配与跨文档操作；证明各入口复用同一合同、权限、回执和失败语义。多步整体预览、整任务撤销与沙箱脚本按独立场景评估。 |

验收覆盖同名对象/重复 occurrence、PINNED/历史快照、共享定义影响、查询截断、过期候选、并发人工编辑、提交前后断线、重复请求、求解失败及显示失败。后端定向测试和真实 Worker 集成与浏览器/WebGL 验收分别记录，静态设计不计为通过。

Token 效率以同一任务的成功率、总输入/输出 token、缓存命中、调用轮数、修复次数和端到端延迟衡量；固定模型/版本与任务集，对比模型规模及上下文压缩前后结果。具体模型、SDK、接口 schema、配额和性能阈值在首批实测后确定。
