一个有效导入 Solid：827 Face、2169 Edge、1390 Vertex，包含 256 个三次 BSpline 面；冻结 BREP 约 4.94 MB，体积约 620928.47 mm³。圆草图半径 15.596120225694847 mm，原点零，X 方向 +X、支撑法向 −Y；反向切除 40 mm，再改为 41、42 mm。精确 Profile、默认 0.02 mm / 0.12 rad 显示策略保持一致。

原始模型不随仓库分发，也不以可清理的开发文档 ID 作为复现前提。输入 SHA-256 和完整草图平面记录在 JSON；没有同一 BREP 时，以下性能数字不能直接类比其他模型。

这里的 hover 数字只计引擎调用 CPU，不含 GPU 完成；Chromium/SwiftShader 的截图同步仍有明显成本，不能据此声称目标显卡 60 Hz。Product 测量选择其中一个完整 occurrence，并验证重复实例共享 mesh、各自覆盖；不是大装配或任意开放结果的容量验收。精确稳定引用、历史全量等价、冷算、取消和共享资源寿命继续独立检查。完整机器样本在同页 JSON 的 `incrementalOptimization20261110`；原始本机材料在 `build/performance/part-incremental/`。

### 算法定位与实现

逐面计时定位到机械板上下两个各有 451 条 wire 的裁剪平面。独立试验用同一份冻结的 STEP 派生 BREP（355183 字节，SHA-256 `80e930ef1607f71b48aa2adf45e8e29807c1da225f12556d2434fd7725b42979`），每种策略从无剖分的深拷贝开始：

| 单次原生算法对照 | 剖分耗时 | 三角形 | 有向边界节点使用数 |
|---|---:|---:|---:|
| 原默认 OCCT 工厂 | 2828 ms | 127812 | 129648 |
| 只取消平面全曲面偏差控制（诊断对照） | 3269 ms | 127812 | 129648 |
| 仅平面改用内置 Delabella | 206 ms | 127812 | 129648 |

研究依据为 Shewchuk 的[三角剖分算法与数据结构对照](https://www.cs.cmu.edu/~quake/tripaper/triangle2.html)及[稳健几何谓词](https://www.cs.cmu.edu/~quake/robust.html)：算法、点定位与存储组织应单独比较，速度不能靠削弱数值判定获得。它们是研究依据，不证明 OCCT 某个函数的渐近复杂度。本轮复用已有依赖的 [OCCT 7.9.1 Delabella 工厂](https://github.com/Open-Cascade-SAS/OCCT/blob/V7_9_1/src/BRepMesh/BRepMesh_DelabellaMeshAlgoFactory.cxx)，没有引入 Triangle、新依赖或修改精确 BREP 算法。

长链另有三处实现调整：

- 显示贡献按历史 transition 归并，每步读取此前状态、统一提交本步写集，去掉反复复制全部状态的 `∑|Sᵢ|` 成本；同引用的 UNCHANGED 共享不可变归属集合。完整值键只在调用内准备，成员别名才需要反向摘要索引；摘要字符串一次构建，避免逐段重复复制。
- Naming v2 逐条装配，省去整份 protobuf FeatureResult 中间数组；完整字节键哈希查找仍按首次出现赋号。冻结原编码器的字节摘要和原显示投影摘要，验证格式、归属、成员及排序未变。
- 检查点只复制共享构造上下文的索引，工具、Body 阶段及范围基底由不可变对象持有；实际重执行才复制所需工具。完整原生历史、最终 Naming 和部分索引复制仍存在，未实现全链常数开销。

`BenchmarkFeatureAssociationHistory` 的 1000 步合成 Naming 微基准为 922 → 41 ms，累计分配约 1.62 GB → 80 MB，每档仅 3 次迭代、一次运行。它只执行 26 个关联元素的历史归并，不能当作 1000 个实体 Feature 的验收。真实 100 次切除夹具的独立 Go pprof 中，贡献索引累计分配读数约 1713 → 231 MB，总累计分配约 5740 → 4129 MB；采样包括建模与冷验，且不计入上表三组计时。它不是 live heap、单次峰值或 RSS。第 100 步当前 Worker RSS 基线约 402～571 MiB、本轮约 287～401 MiB，样本有明显波动，尚不能据此断言长期稳态内存。

### 改动及查询边界

持久 AVL 序列共享未变化行和片段；完整有序来源列表按值共享，写访问分离，并保护已有可变借用和独立读者。计费只统计最终保留的节点/来源存储。该片段共享思路参考 [Ropes: an Alternative to Strings](https://research.google/pubs/ropes-an-alternative-to-strings/)，实现使用 AVL，不声称实现论文全部算法或获得其复杂度定理。

Gear Cover STEP 对应 1265 Face、3210 Edge、1921 Vertex，其中 531 个 B-spline 面。对同一圆形边分别做半径 1、1.1 mm 的 Fillet；冻结导入根在另一个进程准备，首次计时 Worker 没有预加载 BREP，也没有圆角结果缓存。

| --- | --- | --- |
| 首次新圆角完整 RPC | 7999 ms | 2002 ms（1994～2009） |
| 改半径，实际重新执行 | 7135 ms | 1497 ms（1492～1499） |
| 首次 Naming 内核 | 1781 ms | 156 ms |

首次约减少 75%，改半径约减少 79%。每次同半径结果 BREP SHA 与原基线完全一致；冷算的 BREP 也一致，显示结果均为 871323 三角形。Naming 证据策略更新为 v8，不要求与 v7 的 Naming 字节相同；原生及 Router 验证覆盖当前策略下的冷/热 Naming 一致、旧引用、上游插入、Undo/Redo 与候选不改 Head。各阶段存在包含关系，不能把 mesh、display、artifact I/O 重复相加。

这里取消了整体/差量体积积分及 Naming 的面积、边长、质心预计算；用带来源的 BREP 校验事实、实体方向/内部材料分类和实际布尔分区检查替代。正常 Feature 的真实体积积分调用为 **0**；原基线的计数器漏记过两次整体积分，不能据旧数值 0 断言没有积分。新证据/网格继承只接受原生复制关系或一对一 typed history 加完整相同的支撑/裁剪证据，不能按几何近邻建立持久身份。当前首次仍全部剖分，改半径也需要重算边界闭包，尚未实现持久面包冷恢复或跨 GLB GPU/BVH 增量。

后端属性是冻结几何上的显式查询，不写入 Artifact/Revision，缓存仅易失且有界。浏览器验收确认折叠属性栏时选择 Face/Body 不发属性请求；展开后按当前选择查询，关闭后停止新查询，Head 不变。当前及历史 Body、上游阶段及投影几何的查询也经真实 Router 验证。独立整体精确查询返回体积 163655.24665368008 mm³，与原值相差约 3e-11；这一查询含面积/质心，单次耗时 **9.87 s**，不计入 Feature。高精度查询自身仍需后续优化，部分积分暂不可中断。

在源 BREP 已加载的三个独立 Worker 中，分别在 100、650、1100 ms 取消；客户端取消约 0.18～0.27 ms，紧随的拓扑查询等待队列约 31～67 ms、完整返回约 32～117 ms。取消后重新执行均得到同一 BREP SHA，没有把不完整网格接纳为成功结果。这是三个取消时点的样本，不能作为所有 OCCT 算子的中断延迟上界。

新进程首次样本的 RSS 高水位中位数约 393 MB，基线约 390 MB；连续修改后累计高水位约 565 MB。面包按真实保留载荷计费，预算仍为 128 MiB；该费用不等于全部进程内存上界，也没有证明整体 RSS 下降。另一个 32 MiB BIN 的 Go 元数据装配微基准，累计分配从 144389053 降至 47384 B/op（180→149 allocs/op，22.4→0.858 ms）；这是内存流到 discard，不含存储/网络/最终摘要，不能当作整次请求峰值。

通用性证据包含原生 211 个场景及真实 Router 的 Fillet/Chamfer/Draft/Shell、Boolean、孔、切除、关联方向、曲面缝合/封闭、开放 STEP/BREP；新测试数值断言显式查询，不把派生质心重新塞进 Naming。120 次持续新增 boss 的单个 Router 样本共有 242 个 Feature、426 Face / 912 Edge / 608 Vertex；第 120 次追加约 580 ms，末端改参数约 590 ms，均执行 1 阶段/复用 120，随后核对冷 BREP/Naming 与旧引用。该样本没有本轮同身份前后对照，不提供通用长链延迟保证。

浏览器还验证了运行中候选的直接确认只发起一次该候选预览、只生成一个实体特征与最终版本，以及曲线预览遮挡、整体缝合曲面选择、关联方向编辑/历史。所用 Chromium 为软件 WebGL；没有测 GPU 帧率、浏览器 P95 或工业规模。Shell 特殊顺序组装的全局包含性仍有[已知限制](../architecture/current/shell-algorithm.md#性能与限制)，不能把本轮高效有效性检查描述为完整几何语义证明。
