# 表面距离渐近缩放验收

日期：2026-10-17；基线 `e3ee3f4b28331b60ee13b44c9b46b21719530b98`，起始工作树干净。本轮修改前端导航数学、显示射线查询及邻近验证；没有修改持久模型、重置数据、下载浏览器或增加依赖。当前算法与入口见[导航实现](../../web/apps/cad/src/cad/navigation/README.md)。

## 根因与修改

上一轮修复了 near 过小导致背面边线透出的深度精度问题，但缩放数学仍按眼点到旋转中心的距离乘指数。中心位于实体内部时，这个距离不是距表面的距离，仍会让眼点越过前表面。

使用生产 NavigationController / Picker / Rig，20×20×20 盒体、眼点 (0,0,30)、旋转中心为原点，每次拖动 deltaY=-120：基线 CATIA 第 3 次进入实体，眼点 Z=8.664181；SOLIDWORKS 第 4 次进入，Z=7.107833。`build/agent-check/zoom-easing/reproduce.mjs`、`before.json` 和 `before.log` 保存该复现。修复后同样 8 次输入始终在表面外，CATIA Z=10.762243、SOLIDWORKS Z=11.155392，见 `after.json`。脚本读取当前源码，重建故障基线需先恢复基线版本。

三种模式现在共用表面距离曲线。放大前沿眼点到缩放锚点的实际移动方向查询最近的可见 Mesh；点、边、悬停点和辅助网格不参与阻挡。设距锚点为 d、距首先命中表面为 s、安全间距为 ε，极限距离为 `L=max(ε,d-s+ε)`，放大后的距离为 `L+(d-L)·exp(0.003·deltaY)`。CATIA 保留 1.15 输入增益。ε 为命中 Mesh 世界包围球直径的 0.1%，附加小几何与大坐标下的浮点精度下限。已经更近时保留当前眼点，不强制推回。

相同输入的位移随剩余距离逐渐减小，极大单次输入也不会越过首先命中的表面。缩小沿相同表面参考恢复倍率，在极限处保留安全间距尺度的退出步幅，避免锁死或因内部旋转中心而一步退得过远。无表面命中时使用 rig 原有的最小距离；平行投影维持原有 zoom 算法。相机与 pivot 围绕同一锚点同比例变化，离中心锚点的屏幕位置保持。

另外修复透视 dolly 的对象别名问题：默认锚点直接引用 pivot，原来的 `pivot.sub(center)` 会把两者同时清零。现在先复制锚点，非原点模型的连续拖动缩放不再将中心误改为世界原点。

## 实际浏览器数据

证据相对 `build/agent-check/zoom-easing/`。使用已有 Chromium + SwiftShader，生产 InputManager 接收 Playwright 的原生 wheel 或 Ctrl/Shift+中键拖动事件，通过生产导航模块及 CadMaterialFactory / CadShaderLibrary 渲染。盒体尺寸为 20，中心平移到 (250,-180,75)，35° 透视、600×600 canvas，初始距前表面 20；安全间距约为 0.034641。以下是各 32 次等幅放大的渲染世界单位数据，不是物理单位或所有模型的上限保证。

| CATIA Ctrl+中键 | 6.768238 | 0.000018061 | 0.034676232 | 0.052442124 |

完整样本为 `surface-easing-default.json`、`surface-easing-catia.json`、`surface-easing-solidworks.json`；所有样本眼点都在盒体外、near 小于表面间距、中心像素持续为外表面着色 `[67,112,164,255]`。两种拖动模式的 pivot 始终为 (250,-180,75)。对应 `surface-easing-*.png` 已检查，截图为隔离 WebGL fixture，并非真实 API 文档验收。
