# 文档维护

目标是让 Agent 通过少数入口了解项目意图、系统边界与任务归属，再按问题加载证据。优化必要阅读量，不以文档总量最小为目标。[根指南](../../AGENTS.md)定义全局规则，本页拥有文档结构与维护方法。

## 目录与所有权

```text
AGENTS.md                         全局约束与模块路由
README.md                         项目说明、运行入口、可执行单元
<module>/AGENTS.md                 领域规则、符号入口、局部验证
<module>/README.md                 职责、接口、配置、运行、故障
docs/README.md                    紧凑项目地图与按问题路由
docs/architecture/current/        当前领域语义、跨模块调用链、限制
docs/architecture/target/         长期设计、质量门、候选
docs/development/                 环境、Agent 工作流、文档维护
docs/guides/                      操作合同、UI 组件、人工检查步骤
docs/references/                  外部资料来源与适用边界
docs/validation/                  定向实测、调查与未验证项
plans/                           未完成工作与退出条件
tests/test.data/                  静态输入、语料、截图、机器合同数据
build/                           生成报告、临时记录、日志和制品
```

知识目录由 `README.md` 导航，`docs/` 中非索引文件使用稳定的语义化 kebab-case 名称。标题独立可读，使用相对层级，不沿用旧整本架构书的 `4.3.34` 等编号。schema 版本写在合同内容中；命令、policy、fixture 等稳定机器标识不随文档改名。

## 事实与意图

| 信息 | 归属与要求 |
|---|---|
| 当前系统实际做什么 | current 或模块 README；给源码/测试入口，冲突时先核对代码、迁移及实际调用链 |
| 希望系统如何工作 | target；标明已有基础、缺口、候选及范围，不暗示已交付 |
| 下一步做什么 | plans；只写剩余工作、依赖和退出条件，不自行给候选排开发优先级 |
| 如何操作和人工检查 | guides；动作步骤与验证结果分开，步骤存在不代表已执行 |
| 实测结论与验收边界 | validation；保留环境、范围、计时定义、实际结果与未验证项，原始输出归 build，结果不是长期保证 |
| 临时执行状态 | 会话/Issue 或 build；不写入 AGENTS 与长期架构 |

完成计划时把可证实的行为并入 current，删除已完成条目；未执行的验收继续保留。参考软件的行为、设计合同、当前实现和验收证据分别标识。

说明文档描述最终算法、接口、操作方式、验证入口和限制。已解决问题的探索步骤、失败重试、开发文档 ID、临时 Revision/制品/诊断编号不进入长期说明；需要时从 Git 和 `build/` 原始报告追溯。示例使用可重建的几何族或占位 ID，不能依赖会被清除的开发数据。性能测量保留环境、输入定义与统计范围，但不重复修复过程；未解决问题移入 plans，不因清理记录而宣称已解决。

## 最小读取契约

首次接触：根 AGENTS → 项目地图。局部开发：根 AGENTS → 一个局部指南 → 符号和测试；仅在语义边界需要时读取对应 current/target。

主题正文先给用途/事实边界与关键调用链，再给实现、限制及验证入口。摘要与详细合同放在同一主题，避免另建一份易漂移的 quick reference。索引描述“去哪里”，模块 README 描述“怎么运行”，不反复复制功能长表。

## 整理与验证

1. 检查工作区，定位主题、调用方及已存在的权威说明。
2. 移动时同步 Markdown、源码注释、工具内路径；保留资源相对链接，标题改变时修正锚点。用 Git 历史追溯，不加旧路径跳转页。
3. 新文档加入所属索引，确保根 README/AGENTS 可经链接找到。不要只用反引号列出路径。
4. 运行 `invoke context-audit`，修改审计时运行对应 Python 测试，最后 `git diff --check`。

审计验证本地路径/锚点、围栏、指南尺寸、知识目录及文档可达性；静态可达不证明内容正确。`python tools/documentation_audit.py --baseline <git-revision>` 可比较字节数与入口链。字节是可复现代理指标，不是模型 token 数，也不证明任务耗时改善；入口链不含实际源码、测试读取或系统注入成本。
